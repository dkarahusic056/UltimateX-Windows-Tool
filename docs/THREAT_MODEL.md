# Threat Model – ULTIMATE X Windows Control

Methode: STRIDE-orientiert, pro Risiko Gefahr · Auswirkung · Wahrscheinlichkeit · Schutzmaßnahme · Rest-Risiko (§91).
Vertrauensgrenzen: (1) Benutzerkontext ↔ Adminkontext (UAC), (2) App ↔ Netzwerk, (3) App ↔ Dateisystem/Registry, (4) App ↔ Eingaben des Benutzers.

| ID | Gefahr | Auswirkung | Wahrsch. | Schutzmaßnahme (umgesetzt) | Rest-Risiko |
|---|---|---|---|---|---|
| T-01 | **Manipulierte Updates** | Codeausführung | mittel | `AppUpdateService`: Manifest nur per HTTPS (keine Redirects, max. 64 KB), MSI per HTTPS (max. 1 GB), SHA-256-Vergleich, Authenticode gültig UND gleicher Thumbprint wie die laufende App, erneute Prüfung direkt vor dem Start (TOCTOU), fester Ablageort, unsignierte Dev-Builds installieren nie Updates. Update-Quelle ändern erfordert Authentifizierung; manipulierte Config mit Nicht-HTTPS-URL wird verworfen. | gering |
| T-02 | **Command Injection** | Ausführung beliebiger Befehle, ggf. als Admin | mittel | `CommandCatalog`-Allowlist (Enum), kein Shell-Aufruf, `ArgumentList`, strikte Parameter-Validierung (Laufwerk A–Z, Countdown 0–600, Hostnamen per Regex). Helper validiert erneut und akzeptiert nur Tokens `[A-Za-z0-9:_-]`. Uninstall-Strings fremder Programme werden **nie** ausgeführt. Tests: `CommandCatalogTests`. | sehr gering |
| T-03 | **Path Traversal** | Löschen/Ändern von Systemdateien | mittel | `PathGuard`: Kanonisierung, nur absolute lokale Pfade, keine UNC/Device-Pfade, geschützte Wurzeln (Windows, System32, Program Files, Boot, EFI, Recovery), Reparse-Points werden nicht verfolgt. Tests: `PathGuardTests`. | gering |
| T-04 | **Kompromittierte Downloads** | Malware | mittel | Treiber/Windows-Updates nur über die Windows Update Agent API (Microsoft-signiert); Software nur über winget mit validierter Paket-ID; App-Updates siehe T-01. Nichts wird ohne Bestätigung ausgeführt. Speedtest-Daten werden verworfen. | gering |
| T-05 | **Unsignierte Treiber** | Kernel-Kompromittierung | gering | Treiber ausschließlich über Windows Update (WHQL, Hardware-ID-gebunden), je Update einzeln, Authentifizierung + UAC + vorheriger Restore Point. Keine Drittanbieter-Treiberportale. **Bewusst kein WinRing0** (CVE-2020-14979). | sehr gering |
| T-06 | **Dependency-Angriffe** | Supply-Chain | mittel | Nur Microsoft-/.NET-Foundation-Pakete, zentrale fixe Versionen, Lock-Files im CI erzwungen, `dotnet list package --vulnerable` blockiert Release, SBOM. | gering |
| T-07 | **Lokale Rechteausweitung über Helper-Ausgabe** | Admin-Schreibzugriff auf beliebige Datei (Symlink/Hardlink) | mittel | Seit v1.1 schreibt der Helper **keine Ausgabedateien** mehr; die Ausgabe läuft ausschließlich über die abgesicherte Named Pipe (T-28). Altdateien aus v0.x werden ohne Reparse-Point-Verfolgung bereinigt. | sehr gering |
| T-08 | **Austausch des Admin-Helpers** | Codeausführung als Admin | gering | Installation unter `Program Files` (nur Admin-schreibbar). Bei signierter App muss der Helper gültig und mit demselben Zertifikat signiert sein, sonst kein Start. | sehr gering |
| T-09 | **Manipulierte Programmdateien** | Codeausführung | gering | Startprüfung `GetAppIntegrity`: ungültige Signatur (Tampered) → App startet nicht. | gering |
| T-10 | **Manipulierte/kaputte Config** | Fehlverhalten, Absturz | mittel | Größenlimit, Enum-/Wertevalidierung (`Sanitize`), bei Fehler Backup + sichere Standardwerte. Keine sicherheitsrelevanten Freigaben in der Config. | sehr gering |
| T-11 | **Manipulierte Logs** | Irreführung | mittel | Logs sind Benutzerdaten; ungültige Zeilen werden übersprungen. Keine Entscheidungen auf Basis von Logs. | akzeptiert |
| T-12 | **Unbefugte Nutzung am entsperrten PC** | Sensible Aktionen durch Dritte | mittel | Windows Hello für sensible Aktionen, kurze Security Session (0–5 min), sofortiges Ende bei Sperre/Benutzerwechsel/LOCK, UAC für Admin-Aktionen. Fallback ohne Hello: explizite Bestätigung + UAC. | mittel (ohne Hello) |
| T-13 | **Datenabfluss / Privatsphäre** | Offenlegung von MAC/IP/Seriennr. | mittel | Maskierung standardmäßig, Reports ohne sensible Daten, Netzwerk nur auf Benutzeraktion (Public IP mit Hinweis, Speedtest mit Hinweis), keine Telemetrie. | gering |
| T-14 | **MITM bei Netzwerkzugriffen** | Falsche Daten | gering | Nur HTTPS, TLS 1.2/1.3, Standard-Zertifikatsprüfung, keine Redirects, Antwortgrößen begrenzt, Inhalte validiert (z. B. IP-Parsing). | gering |
| T-15 | **Unsichere Plugins** | Codeausführung | – | Es gibt kein Plugin-System. Erweiterungen nur als signierter Code im Hauptprodukt. | n/a |
| T-16 | **Denial of Service durch Systemabfragen** | Hänger | mittel | WMI-Timeouts, Abfragen im Hintergrund, Event-Log-Mengen begrenzt, Speedtest/Ping mit festen Grenzen. | gering |

| T-17 | **winget-Argument-Injection** | Installation fremder Pakete / Parameter | mittel | Paket-ID per Regex `^[A-Za-z0-9][A-Za-z0-9.+_-]{0,127}$`, feste Argumentliste (`--exact`, kein `--override`), keine Shell. | gering |
| T-18 | **Missbrauch der Helper-Aktion „Autostart HKLM“** | Persistenz für Malware | mittel | Helper legt nie Einträge an, schaltet nur bestehende Run-/StartupFolder-Einträge um (Existenzprüfung), Name per Base64url-Token, keine Pfade. | gering |
| T-19 | **Laden einer fremden nvml.dll** (DLL-Hijacking) | Codeausführung | gering | Nur `System32\nvml.dll`, nur bei gültiger Authenticode-Signatur mit Herausgeber NVIDIA; Laden per absolutem Pfad. | sehr gering |
| T-20 | **Datenverlust durch Cleaner** | Löschen persönlicher Dateien | mittel | Feste Kategorien (Temp, Thumbnail-Cache, WER, Shader-Cache, Papierkorb), `PathGuard` je Datei, keine Reparse-Points, Temp nur > 24 h, schreibgeschützte/gesperrte Dateien werden übersprungen, Vorschau + Bestätigung, Papierkorb zusätzlich Authentifizierung. | gering |
| T-21 | **Datenverlust durch Desktop Organizer** | Dateien verschoben/gelöscht | gering | Ändert ausschließlich Symbolpositionen über `IFolderView`, keine Dateisystem-Operation; Layout-Backup vor jeder Änderung, Wiederherstellung. | sehr gering |
| T-22 | **SQL-Injection / beschädigte Datenbank** | Fehlverhalten | gering | Nur parametrisierte Statements, keine Eingaben in SQL; beschädigte DB wird beiseitegelegt und neu angelegt. | sehr gering |
| T-23 | **Windows Update Search-Kriterium-Injection** | Installation falscher Updates | gering | UpdateID muss eine GUID sein (`Guid.TryParseExact`), Prüfung in App und Helper. | sehr gering |
| T-24 | **Verwundbarer Kernel-Treiber für Sensoren** | Rechteausweitung über Treiber (z. B. WinRing0) | hoch | ULTIMATE X installiert/lädt keinen Treiber. Sensoren nur aus Grafikkernel (D3DKMT), ACPI-Leistungsindikator, SMART (Helper) sowie *lesend* aus HWiNFO-Shared-Memory/LibreHardwareMonitor-WMI; Größen/Offsets im Shared Memory werden gegen die View-Größe geprüft. | gering |
| T-25 | **Missbrauch des Netzwerk-Scanners** | Scannen fremder Netze | mittel | Nur private Subnetze eigener aktiver Adapter, max. 1024 Adressen, nur Ping/ARP; Portprüfung nur auf Klick für ein Gerät im gescannten Subnetz, feste Liste von 20 Diensten; Hinweis + Bestätigung beim ersten Scan; Protokollierung. | gering |
| T-26 | **Absturzabbilder enthalten Speicherinhalte** | Offenlegung sensibler Daten | mittel | Dumps verlassen nie den Rechner und werden nicht kopiert; der Helper liest nur den Dateikopf. kd.exe nur aus Program Files, Signatur „Microsoft“ geprüft, `-noshell`, Symbole ausschließlich vom Microsoft-Symbolserver (HTTPS); Dump-Name per Regex (kein Pfad). | gering |
| T-27 | **Benchmark füllt Datenträger** | Systeminstabilität | gering | Nur lokale feste Laufwerke, mindestens 2× Testgröße + 2 GB müssen frei bleiben, Testdatei wird im `finally` gelöscht, RAM-Test passt Puffergröße an freien Speicher an. | sehr gering |
| T-28 | **IPC-Spoofing / Pipe-Squatting zwischen App und Admin-Helper** | Gefälschte Ausgabe, Abgreifen der Admin-Ausgabe, Token-Übernahme | mittel | Named Pipe mit zufälligem Namen (Run-ID), von der App **vor** dem Helper-Start mit `FirstPipeInstance` angelegt; ACL nur aktueller Benutzer + Administratoren, Netzwerk verweigert; App prüft Client-PID = selbst gestarteter Prozess; Helper prüft Server = `UltimateX.exe` aus dem eigenen Installationsordner und verbindet mit Impersonation-Level *Identification*; 256-Bit-Sitzungs-Nonce + streng steigende Sequenznummer (Replay-Schutz); Längenpräfix, max. 64 KB/Rahmen, 16 MB/Lauf, strikte Schema-Prüfung, Zeitlimits; bei Verstoß wird die Ausgabe verworfen (fail closed) und ein Sicherheitsereignis protokolliert. Über die Pipe werden keine Befehle übertragen. Tests: `HelperPipeProtocolTests`. | gering |
| T-29 | **Datenabfluss über PC-Bericht (PDF/Druck)** | Offenlegung von IP/MAC/Namen/Seriennummern | mittel | Datenschutzmodus standardmäßig AN (maskiert IP, MAC, Benutzer-/Computername, Seriennummern, Gateway/DNS; keine öffentliche IP); Abschalten nur nach Windows-Hello-Bestätigung + Security-Log; Vorschau zeigt vor dem Export, welche Daten enthalten sind; Abschnitte einzeln abwählbar. Tests: `PdfReportTests` (Maskierung im PDF-Inhalt). | gering |
| T-30 | **Privatsphäre bei Komponententests (Kamera, Mikrofon, Tastatur, Maus)** | Unbemerkte Aufnahme | mittel | Kamera/Mikrofon nur auf ausdrücklichen Klick; Kamera wird im Nur-Lese-Freigabemodus geöffnet und sofort freigegeben, kein Bild wird erzeugt; Mikrofon wertet nur den Pegel aus, Puffer werden überschrieben und genullt; Tastatur/Maus nur im eigenen Testfenster, keine globalen Hooks. | sehr gering |
| T-31 | **Destruktive Tests** | Datenverlust | gering | Standard: nur lesende Prüfungen; Datenträger-Schreibtest nur nach Bestätigung, ausschließlich in eine neue, eindeutig benannte Temp-Datei (`CreateNew`), SHA-256-Vergleich, Löschen im `finally`, Mindest-Freiplatz. RAM-Mustertest nur in eigenem Puffer. | sehr gering |
| T-32 | **Ping-/Hostnamen-Injection (Quick Ping, Live Ping)** | Befehlsausführung | gering | Ping ausschließlich über `System.Net.NetworkInformation.Ping`, keine Shell; Ziel per `InputValidator` (IP oder RFC-1123-Hostname). Tests: `LivePingTests`. | sehr gering |
| T-33 | **Gefälschte Sensorwerte (fremder Prozess erzeugt HWiNFO-Shared-Memory)** | Falsche Anzeige | gering | Nur lesend, Größen/Offsets geprüft, Plausibilitätsgrenzen; jeder Wert zeigt seine Quelle; keine Sicherheits- oder Abschaltentscheidungen auf Basis von Sensorwerten. | akzeptiert |
| T-35 | **Manipulierte Office-Installation (TOCTOU)** | Fremder Prozess tauscht `setup.exe`/`configuration.xml` zwischen Prüfung und erhöhtem Start | mittel | Download nur von `officecdn.microsoft.com` (HTTPS, Weiterleitungen einzeln gegen die Domain geprüft, Größenlimit); Konfiguration wird geschrieben, dann `setup.exe` und `configuration.xml` mit `FileShare.Read` gesperrt (kein Ersetzen/Umbenennen/Löschen), Inhalt der Konfiguration verglichen, Authenticode „Microsoft Corporation“ geprüft und erst dann per UAC gestartet; Sperre bis nach dem Start. Der Admin-Helper lehnt `OfficeDeploy` grundsätzlich ab (keine Helper-Ausführung aus benutzerbeschreibbaren Ordnern). | gering |
| T-36 | **Software aus manipulierter Quelle (New PC Setup)** | Malware statt Originalinstaller | hoch | Nur Pakete aus dem festen `SoftwareCatalog` (winget-ID per Regex, Store-ID 12 Zeichen); vor jeder Installation `winget show`: Installer-URL muss HTTPS sein und zur hinterlegten Herstellerdomain gehören (exakter Host oder Subdomain; bei GitHub nur der Pfad des offiziellen Repositorys), Filehoster/Download-Portale/URL-Kürzer immer gesperrt, keine Zugangsdaten in der URL, SHA-256 im Manifest Pflicht (winget prüft den Hash beim Download); Installation über `--exact --source winget`, alles im Installationsprotokoll. | T-37 | **ClamAV-Pfad-/Argument-Injection** | Scan fremder Netzlaufwerke, Optionen einschleusen | gering | Scanziel als eigenes Argument (`ArgumentList`), muss vollständiger lokaler Pfad sein; UNC-/Gerätepfade in jeder Schreibweise (`\\`, `//`, `\\?\`), relative Pfade, Optionen (`-…`), Anführungszeichen und Wildcards abgelehnt – vor und nach `GetFullPath`; ClamAV-Programme nur aus `Program Files\ClamAV`, Daten unter `%LOCALAPPDATA%\UltimateX\clamav`, eigene Daten per `--exclude-dir` vom Scan ausgenommen. Tests: `ClamAvCommandTests`. | sehr gering |
| T-38 | **Schwächung des Virenschutzes** | Nutzer verliert Echtzeitschutz | mittel | ClamAV ist ausschließlich Zusatz-Scanner auf Anforderung; ULTIMATE X deaktiviert, konfiguriert oder deinstalliert Microsoft Defender nie und bietet das auch nicht an. Installation erst nach Online-Prüfung des Projekts (aktiv gepflegt, nicht archiviert). | sehr gering |
| T-39 | **Websuche / Links** | Öffnen schädlicher Adressen, Datenabfluss über Suchbegriffe | gering | `UriLauncher` öffnet nur `https:`/`ms-settings:`; Suchbegriffe werden vollständig URL-kodiert (`Uri.EscapeDataString`) und enthalten nur Modellnamen/RAM-Größe/Windows-Version – keine Seriennummern, Benutzer- oder Netzwerkdaten; ULTIMATE X ruft Suchergebnisse selbst nicht ab. | sehr gering |

## Grenzen

ULTIMATE X ist nach dem Prinzip *Secure by Design* gebaut, aber keine Software ist „100 % unhackbar“. Ein Angreifer mit Administratorrechten oder Kernel-Zugriff kann jede Anwendung auf dem System manipulieren; ULTIMATE X kann ein bereits kompromittiertes System nicht zuverlässig erkennen oder schützen. Die Maßnahmen oben reduzieren die Angriffsfläche der App selbst.

## Bewusst nicht umgesetzt (aus Sicherheitsgründen)

- **Temperatursensoren über WinRing0/InpOut** – verwundbare Kernel-Treiber. Alternative: Herstellerschnittstellen (NVML/ADLX), Storage-API für NVMe.
- **Windows Update deaktivieren**, **Defender/Firewall abschalten**, **UAC umgehen** – werden nie angeboten.
- **Fremde UninstallStrings ausführen** – Deinstallation über Windows „Apps & Features“.
- **FPS-Messung per DLL-Injection/Present-Hook** (v1.3) – Anti-Cheat-Risiko und Instabilität; stattdessen ETW (T-44).
- **Schattenkopien (VSS) für das Datei-Backup** (v1.3) – erfordern Adminrechte für jeden Lauf; geöffnete Dateien werden stattdessen übersprungen und gemeldet.
- **Windows-Aufgabe für Backup-Zeitpläne** (v1.3) – keine Persistenz außerhalb der App; Zeitpläne laufen nur bei laufender App.
- **Freie DNS-Server-Eingabe, Portbereiche/Portscans, Aufwecken über das Internet** (v1.3) – Missbrauchspotenzial (T-49, T-50).
- **Automatisches Zurückspielen von Treibern** (v1.3) – nur Anleitung (pnputil/Geräte-Manager).
